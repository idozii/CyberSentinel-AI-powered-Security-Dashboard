# Steps 36-38 - Explicit security boundary and release limitations

1. **Step 36:** Multi-owner PostgreSQL tests use ephemeral localhost Postgres in CI. Synthetic `.org` claims get test-only TXT lookup injection, never DNS overrides in production. The role's `cs.actor_id` is a client-set custom Postgres GUC. A compromised `cybersentinel_runtime` credential can impersonate a UUID actor through direct SQL; RLS does not defend that threat. Accordingly these are backend-scoped isolation regression tests, NOT proof of tenant safety after runtime credential compromise. Independent architecture/security review is a hard NO-GO item.
2. **Step 37:** Aggregate local outbox counts and offline migration checks provide no guarantee of live site availability, 24x7 monitoring or incident response. Old event timestamps are never modified and a stale/full queue is flagged for action.
3. **Step 38:** Backups are owner-only SQLite database files holding pseudonymous event metadata, not raw NGINX lines or plain bearer keys. They are not encrypted at rest and do not cover Neon PostgreSQL. Restore is create-only, opt-in and must not be used concurrently with an active watcher. SQLite consistency checks do not replace system-level durability checks, recovery-time drills, encryption and protected remote backups.
4. Existing Auth0/OIDC, tenant scopes, DNS verification, public ingest exposure and migrations are NOT modified by this patch. The release workflow runs no remote network and remains **beta_gate: blocked**.
5. Browser dashboard SOC v2 remains the localhost-only view. An actual product beta still needs a controlled domain, audited TLS deployment, tenant identity security hardening, live monitoring, PostgreSQL backup/restore, consent and a pen-test.
